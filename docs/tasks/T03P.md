## Scope delivered

- WebSocket server at `/ws` with JSON messages `{ type, payload }`.
- `PROTOCOL_VERSION = 4` today (this task shipped 1; v2–v4 are later work),
  `HELLO` version check, `WELCOME`, `STATE`,
  `KEYFRAME`, `REJECT`, `PING` / `PONG`, `ERROR`.
- `CubeWorld`: one cube per player, unique id and color, 20 Hz tick, full
  `KEYFRAME` every `keyframe_interval_ticks`, delta-shaped `STATE` otherwise.
- Client: connects, sends `HELLO`, sends `INPUT` at 20 Hz, renders received cube
  state, reconnects after 3 s on close.
- CORS origin allowlist also gates the WebSocket handshake.
- `config/net_proto.json` populated with 9 values.
- [`docs/protocol.md`](../protocol.md) documents framing, messages, payloads and
  quantization.

## Known limitations

- Movement is client-authoritative and ack-only (F7): there is no server-side
  speed, so `net_proto.move_speed` was removed rather than left looking
  load-bearing.
- `world_bounds` is stored as snake_case in config and read as camelCase, but no live `INPUT` path calls the bounds check.
- Automated tests cover quantization and config loading. There is no movement validator to test: the dead function was removed rather than kept certified.
- No persistence: reconnect creates a new player and cube.
- `STATE` currently sends every cube, not only changed cubes.
- The quick-tunnel origin must be present in `CORS_ORIGINS` or the handshake is rejected with code 4001.
