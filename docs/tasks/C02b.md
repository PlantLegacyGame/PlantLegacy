# C02b: WebGPU Compute-Driven Plant Renderer

**Status:** Partial — v1 slice + impostor baking + VRAM pool + GPU skinning + texture arrays + mutation signatures + planet occlusion implemented; shared depth is still open, so the task stays `[ ]`

**Renderer note (2026-11-14).** This record describes the v1 slice *as built*, when billboards covered tiers 2–4. ADR-042 supersedes the tier mapping for the spec: **L2 is an ellipsoid SDF** and the atlas billboard is **L3-only** (2–12 px, colour only). The implementation description below is left as written because it is evidence of what shipped, not the target design. See `DESIGN.md` Part 14.2.0 for canonical tiers.
**Scope:** GPU-driven plant rendering path with compute culling/LOD, real WebGPU
buffers and shaders, and a WebGL2 fallback.
**Owner:** `config/render.json`
**Dependencies:** C01, C02, C03

## 1. Implementation Summary (v1 slice + impostor baking + VRAM pool + GPU skinning + texture arrays)

1. **Device and fallback plumbing**
   - `WebGPUDevice.ts` requests an adapter/device, filters required features and
     limits, configures the canvas, and reports device loss.
   - `main.ts` probes `navigator.gpu` and `webgpu_enabled`, creates a separate
     transparent WebGPU canvas over the existing Three.js canvas, and falls back
     to WebGL2 when WebGPU is unavailable. Device loss disposes the WebGPU path
     and returns to WebGL2 without recursive callbacks.
   - WebGL keeps rendering the C03 environment (sky, terrain, weather) while
     WebGPU draws plants on the overlay.

2. **GPU buffers and shader loading**
   - Frame uniforms (92 floats / 368 bytes), per-plant storage buffer (48-byte
     stride), and per-plant render output buffer (16-byte stride) are allocated
     and updated per frame.
   - WGSL is imported through Vite `?raw` from `shaders/common.wgsl`,
     `cull.wgsl`, `mesh.wgsl`, and `impostor.wgsl`.
   - `vite-env.d.ts` declares the `?raw` module type.

3. **Compute-driven culling and LOD**
   - A compute pass evaluates each plant against the camera frustum and projected
     pixel size.
   - Tier assignment uses promote/demote hysteresis and a minimum dwell time so
     plants do not oscillate between tiers.
   - Tiers 0/1 select the merged mesh path; tiers 2–4 select the billboard path.

4. **Mesh and impostor passes**
   - `PlantMeshBuilder.ts` builds procedural tapered tubes and leaf cards per
     plant, grouped by root, with growth easing and plant bounds/colors.
   - `mesh.wgsl` draws tier 0/1 merged geometry.
   - `impostor.wgsl` draws tiers 2 and 3 as one analytic ellipsoid per plant,
     ray-traced in a camera-facing quad and relit from the frame's sun.
   - Sun direction, growth, health tint, and the Root Sight highlight are applied
     in the GPU passes.

5. **Impostor (ANALYTIC, 2026-11-24)**
   - No atlas, no bake: the 12 px and below band traces the plant's ellipsoid in
     the fragment shader, so there is no VRAM cost and no readback.
   - The surface gets procedural bark/canopy colour, the plant's composed look
     and the same planet-and-hill occlusion the mesh pass uses.
   - `webgpu_impostor_enabled` switches the pass; the old re-bake interval key is
     gone with the baker.

6. **VRAM pool allocation/budgeting (IMPLEMENTED 2026-11-10)**
   - `VRAMPool` class tracks allocated bytes against configurable budget (default 256 MB)
   - All buffer allocations go through `vramPool.allocate()` with budget enforcement
   - `allocateOrThrow` helper guarantees non-null buffers or throws descriptive error
   - Pool destroyed on renderer cleanup
   - Config tunables: `vramBudgetBytes`, `vramMaxVertexBytes`, `vramMaxIndexBytes`

7. **GPU skinning for 0.9s emergence animation (IMPLEMENTED 2026-11-10)**
   - Vertex buffer now includes 4 joint indices (u32x4) + 4 joint weights (f32x4) = 19 floats = 76 bytes/vertex
   - `PlantMeshBuilder` assigns joint indices/weights per segment for tapered tubes and curved tubes
   - `mesh.wgsl` and `impostor.wgsl` apply skinning via `jointMatrices` storage buffer
   - `writeJointMatrices()` computes identity matrices per joint; growth animation driven by vertex `spawnTime` + `growthProgress`

8. **Texture arrays for plant variation (IMPLEMENTED 2026-11-10)**
   - 5 texture arrays (2D array textures): Bark, Leaf, Flower, SporeSac, Seed — each 256×256×8 layers
   - Procedurally generated at startup with seeded RNG per layer (bark streaks, leaf veins, flower petals, spore bumps, seed teardrop)
   - Vertex packed data includes 4-bit `variationIndex` (bits 25-28) per vertex
   - `mesh.wgsl` samples from the appropriate array based on `nodeType` and `variationIndex`; the impostor pass is procedural and samples none
   - New bind group bindings 3-7 for texture arrays, binding 8 for shared sampler

9. **Debug and verification hooks**
   - `window.__plantLegacy.webgpuRenderer` exposes the renderer.
   - `readRenderData()` asynchronously reads back the render buffer for tier,
     projected size, and visibility checks.

## 3. Config Tunables (`config/render.json`)

**Config drift, resolved 2026-11-16.** The seven settings that used to live as
`WebGPURenderer` constructor defaults or module constants are now config values in
`config/render.json` and are passed in by `main.ts`: `webgpu_impostor_enabled`,
`webgpu_vram_budget_bytes` (256 MB), `webgpu_vram_max_vertex_bytes` (64 MB),
`webgpu_vram_max_index_bytes` (16 MB), `webgpu_texture_array_size` (256 texels) and
`webgpu_texture_array_layers` (16). The impostor pass can be switched off. The
re-bake interval key that used to sit beside the switch is gone with the baker
(2026-11-24): the pass is analytic and bakes nothing.
The former constants `TEXTURE_ARRAY_SIZE` / `TEXTURE_ARRAY_LAYERS` are gone; the
renderer reads `textureArraySize` / `textureArrayLayers` from its config.

| Tunable | Type | Range / Options | Default | Effect |
|---|---|---|---|---|
| `webgpu_enabled` | boolean | `true` / `false` | `false` | Enable the WebGPU plant pass; off by default because its separate depth buffer cannot sort against the terrain (ADR-041) |
| `webgpu_max_plants` | integer | [1000, 65536] | 20000 | Capacity of the plant/render storage buffers |
| `webgpu_tier0_threshold` | integer | [100, 500] | 300 | Projected pixel size at or above which tier 0 (full mesh) is used |
| `webgpu_tier1_threshold` | integer | [40, 150] | 80 | Projected pixel size at or above which tier 1 (mid mesh) is used |
| `webgpu_tier2_threshold` | integer | [6, 100] | 12 | Projected pixel size at or above which tier 2 (the ellipsoid impostor band) is used |
| `webgpu_tier3_threshold` | integer | [1, 8] | 2 | Projected pixel size at or above which tier 3 is used; the same ellipsoid impostor draws it, and below it the plant is a coloured point |
| `webgpu_hysteresis_promote` | number | [1.0, 1.5] | 1.15 | Multiplier applied before promoting to a higher-detail tier |
| `webgpu_hysteresis_demote` | number | [0.5, 1.0] | 0.85 | Multiplier applied before demoting to a lower-detail tier |
| `webgpu_min_dwell_time` | number | [0.1, 2.0] | 0.5 | Minimum seconds a plant stays in a tier before changing |
| `webgpu_impostor_enabled` | boolean | `true` / `false` | `true` | Draw tiers 2 and below as analytic ellipsoid impostors |
| `vram_budget_bytes` | integer | [64MB, 1GB] | 256MB | Total VRAM budget for all WebGPU buffers |
| `vram_max_vertex_bytes` | integer | [16MB, 256MB] | 64MB | Maximum vertex buffer allocation |
| `vram_max_index_bytes` | integer | [4MB, 64MB] | 16MB | Maximum index buffer allocation |
| `webgpu_texture_array_size` | integer | [64, 1024] | 256 | Resolution of each texture array layer |
| `webgpu_texture_array_layers` | integer | [1, 64] | 16 | Number of variation layers per texture array |

## 5. Acceptance Criteria Not Yet Met

The task remains `[ ]` until the following are implemented and verified:

- **Cross-fade between adjacent tiers** — Implemented (2026-11-12). `PlantRenderData` now carries `blendFactor`; the cull shader computes blend progress during tier 1↔2 transitions instead of hard-reverting to the previous tier. Mesh fades out (alpha × (1−blend)) and billboard fades in (alpha × blend) across the mesh/billboard boundary. Both pipelines already support alpha blending, so no render-pass changes were needed.
- **L2/L3 plant mutation rendering** — Implemented (2026-11-13). The three documented signatures render from a per-node bitmask: bits 29-31 of the packed vertex word carry bioluminescent / thickened bark / variegated foliage (`renderers/plant/mutations.ts`, 6 tests). `main.ts` reads the mask off server nodes at every plant sync, `PlantMeshBuilder` bakes thickened-bark radii and per-plant masks, and `mesh.wgsl`, `billboard.wgsl` and the cull pass apply the signatures. Strengths are config: `mutation_bioluminescence_strength`, `mutation_bark_thickness_scale`, `mutation_variegation_strength`.
- **Shared depth between the WebGPU plant pass and the WebGL environment pass** — Not implemented as depth sharing. The two passes run on separate canvases with separate contexts, and no browser exposes a WebGL depth texture to WebGPU without a per-frame readback (option b, which stalls); option (a) means moving the whole C03 environment into WebGPU and option (c) discards the WebGPU path. What is implemented instead is the only occlusion the current world actually has: a planet-body test in `cull.wgsl`. The segment from the camera to each plant is tested against the configured sphere, so plants behind the horizon or on the far side of the globe are culled (verified: `visible 0` behind the planet, `visible 1` with `planetRadius` set to 0). Local terrain relief does not exist yet, so this covers every occluder today; true shared depth stays open and is recorded as such.
