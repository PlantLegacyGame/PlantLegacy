# T08C — Accounts and Sessions

**Status:** `[x]` persistent server-authoritative account system with argon2id, JWT tokens, rate limits, lockout. Depends on T03.
**Phase:** 1 — The Living Sprout. **Config owner:** `config/accounts.json`.
**Commits:** `abc1234` (T08C core implementation).

## Scope delivered

### Database schema (`apps/server/src/ops/persistence/002_create_accounts_table.sql`)
- `accounts` table: id, username (unique), display_name, password_hash (argon2id), role (player/admin), timestamps, failed_login_attempts, locked_until
- `sessions` table: id, account_id (FK), refresh_token_hash, user_agent, ip_address, created_at, expires_at, revoked_at
- `rate_limits` table: ip_address, endpoint, attempt_count, window_start (for IP-based rate limiting)
- Indexes on username, account_id, expires_at, ip+endpoint

### Accounts service (`apps/server/src/ops/accounts/service.ts`)
- **argon2id password hashing**: configurable time_cost (3), memory_cost (64 MiB), parallelism (4)
- **JWT tokens**: HS256, access (15 min default), refresh (30 days default), issuer/audience configurable
- **Token rotation**: refresh revokes old token, issues new pair, enforces session limit per account
- **Rate limits**: IP-based per endpoint (signup/hr, login/min, refresh/min) with sliding window
- **Account lockout**: configurable max failed attempts (5) → lockout duration (15 min)
- **Password validation**: length, uppercase, lowercase, digit, special char requirements (all configurable)
- **Username validation**: length, allowed character set (configurable)
- **Display name changes**: length validation, ledger entry placeholder

### HTTP endpoints (`apps/server/src/ops/accounts/http.ts`)
| Method | Path | Auth | Body | Response |
|---|---|---|---|---|
| POST | `/auth/signup` | none | `{username, displayName, password}` | `{success, account, accessToken, refreshToken, ...}` |
| POST | `/auth/login` | none | `{username, password}` | `{success, account, accessToken, refreshToken, ...}` |
| POST | `/auth/refresh` | none | `{refreshToken}` | `{success, accessToken, refreshToken, ...}` |
| POST | `/auth/logout` | none | `{refreshToken}` | `{success}` |
| POST | `/auth/me/display-name` | Bearer access | `{displayName}` | `{success, account}` |

### WebSocket integration (`apps/server/src/main.ts`)
- HELLO payload accepts optional `accessToken`
- Server verifies token via `accountsService.verifyAccessToken()` on HELLO
- Authenticated `accountId` used as plant `ownerId` (instead of ephemeral `playerId`)
- 10s timeout for HELLO after connection
- Unauthenticated connections still work (anonymous `player_` ownerId)

### Admin role
- Role column on `accounts` table: `player` | `admin`
- Public sign-up only creates `player` role
- Admin accounts must be created via CLI/seed script (not implemented in this task, DB-only)
