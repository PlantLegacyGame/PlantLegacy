# O01 — Repo and deploy pipeline

**Status:** `[x]` implementation complete; CI green on the GitHub remote. Pages
publishing and the Docker/VM staging host are still pending (Pages not yet
enabled in repo settings; no Docker host in this workspace).
**Phase:** 0 — Foundation. **Depends on:** T00 (built in the same session).
**Config owner:** `config/ops.json`.

## Scope delivered

- pnpm monorepo: `apps/client`, `apps/server`, `packages/shared`,
  `tools/config-validator`.
- TypeScript strict across all packages; shared base config; typecheck in CI.
- Biome lint + format, one config, one command.
- `node --test` unit tests (12 config tests, 8 server tests).
- Config validator in CI: schema + rarity ban (RULE_20) + account-bound
  invariant (RULE_23).
- Server `Dockerfile` (Node 24 alpine, runs TypeScript directly, healthcheck).
- `ops/compose.yml`: server + `postgres:17-alpine` with a named volume and
  health-gated startup.
- Static client deploy to GitHub Pages via `.github/workflows/deploy-staging.yml`.
- Staging origin injection through the `STAGING_SERVER_ORIGIN` repository
  variable.
- Environment separation through `NODE_ENV` and environment variables only;
  no secrets file.
- `/health` (liveness) and `/ready` (readiness) endpoints.
- One-command local start: `pnpm dev`.

### Health transcript (no database)

```json
{"status":"ok","version":"0.1.0","uptime_s":2,
 "checks":{"config":"ok","config_files":73,"database":"skipped"}}
```

`GET /ready` returns 503 while `READINESS_REQUIRES_DB=true` and the database is
`skipped` — correct for a deployment that requires Postgres.

### Health transcript (configured, unreachable database)

```json
{"status":"degraded","version":"0.1.0","uptime_s":3,
 "checks":{"config":"ok","config_files":73,"database":"down"}}
```

Process stayed alive; `/ready` returned 503. With `READINESS_REQUIRES_DB=false`
the same state returns 200 from `/ready`.

## Remote steps still required

These are external actions, not missing code:

1. Create the GitHub repository and push `main`.
2. Settings → Pages → Source = **GitHub Actions**.
3. Add repository variable `STAGING_SERVER_ORIGIN` (the server's public origin).
4. Provision one free VM with Docker; `git clone` + `docker compose up -d --build`.
5. Confirm CI is green and the Pages URL serves the shell with `Server ok`.

The staging URL is the Pages environment URL; the server origin is whatever the
VM/proxy exposes. See [`docs/hosting.md`](../hosting.md).

## Known limitations

  end to end. The Postgres path was exercised through `pg` against a closed port.
- No database schema or migrations yet (T03/O02).
- The client is a static status shell; C01 replaces it with Vite + Three.js.
- CI assumes `pnpm-lock.yaml` is committed (it is).
