# D01: Dev Settings Engine

**Status:** `[ ]` — client DevPanel implemented, but missing `?dev=1` gate, server config endpoints, and `config/dev.json`.
**Scope:** A dev-only console that exposes every config system and the key game switches, so behaviour is explicit and editable instead of inferred from hidden client state.
**Owner:** `config/` + `apps/client` + `apps/server`
**Dependencies:** T00, C01, T00A, T01

---

## 1. Why

The 2026-11-07 audit found implicit behaviour that could not be inspected or
changed from inside the game:

- persistence vs session-only play was a hidden client/server key detail;
- germination gate thresholds were unused;
- auto-growth was not a visible switch;
- camera framing, seed scale and plant size class were hardcoded;
- growth costs lived in both config and client code.

ADR-029 makes the default local/dev path session-only and moves every switch
behind an explicit dev surface.

## 2. Required behaviour

1. The client opens the console with `?dev=1` (and a key binding once defined).
2. The console lists every loaded config file and every value with its current
   value, type, range and notes.
3. Values can be edited and applied without editing source files.
4. The key game switches are first-class toggles:
   - persistence (off by default)
   - reconnect window
   - auto-growth (off by default)
   - germination gate
   - germination failure kills the seed
   - plant size class (normal / large / giant)
   - camera start/recenter distance and pan speed
   - resource rates and photo/upkeep rates
   - WebGPU on/off and LOD thresholds
5. A reset action restores the checked-in defaults.
6. The endpoint is dev-only. In production it returns 404 and cannot change
   config.
7. The console never becomes a way for a normal player to cheat in production.

## 3. Current implementation (2026-11-09)

### Client (`apps/client/src/ui/DevPanel.ts`) — **IMPLEMENTED**
A comprehensive DevPanel with 7 tabs already exists and is created in
`main.ts` when `import.meta.env.DEV` (Vite dev mode):

| Tab | Controls |
|-----|----------|
| Time & Weather | Time of day (0–1), weather state, sun intensity, presets |
| Resources | Tile inspector, global resource config, tile actions (fill/drain) |
| Plant | Growth speed, energy, germination thresholds, actions (regenerate, fill energy/biomass, kill) |
| Render | Quality preset, LOD distances, raymarch steps, smin blend, wind, health tint |
| Camera | Smoothing, bounds, presets (top-down, side, close, far) |
| Simulation | Tick rate, interest cell/ring, active/near/dormant rates, offline damage, persistence (force save, clear) |
| Debug | Logging, renderer (toggle WebGPU, reinit, dump shaders), stress test (100/500/1000 plants) |

UI features: draggable, minimizable, searchable, tabbed, CSS-variable themed.

### Missing / Not Yet Implemented

1. **`config/dev.json`** — not created. Should contain `dev_panel_enabled`, `persistence_enabled`, `auto_growth`, `germination_gate`, `seed_size_class`, etc.
2. **`$dev=1` gate** — panel currently shows whenever `import.meta.env.DEV` is true (Vite dev mode). Should only appear with `?dev=1` query param (and a key binding).
3. **Server dev endpoints** — no `GET /dev/config` or `POST /dev/config` guarded by `env !== 'production'`. DevPanel sends `type: 99` (`DEV_RESPONSE`) messages but server has no handler for them.
4. **Config persistence** — edits in DevPanel send to server via `type: 99` but server doesn't validate or write back to `config/*.json`.
5. **Persistence switch** — not wired to world disconnect logic (ADR-029 session-only default).
6. **Key binding** — no keyboard shortcut to toggle panel (backtick is used by debug overlay).

## 4. Acceptance criteria

- `?dev=1` opens the panel; the panel is absent without the flag.
- A non-production server accepts a valid edit and rejects an invalid one with a
  plain reason.
- A production server returns 404 for both endpoints.
- Persistence off: reload and server restart both produce a fresh plant, and a
  disconnect removes the plant immediately.
- Persistence on: the reconnect window works and the once-per-day account prompt
  is eligible.
- Auto-growth off: germination only happens from a player commit.
- Auto-growth on: germination can proceed without a commit, and the HUD says so.
- Germination gate values and current tile values are visible before commit.
- `pnpm verify` is green.

## 5. Not in v1

- Remote admin auth and multi-operator audit logs.
- Editing compiled shaders or arbitrary source from the browser.
- A level editor or terrain sculpting.
