## Scope delivered

### Database schema & persistence (`apps/server/src/ops/persistence/`)
- `001_create_plants_table.sql`: `world_plants` table with binary snapshot (`BYTEA`), append-only event log (`JSONB`), tier tracking, and metadata columns for fast queries. `world_events` table for global events.
- `003_add_refresh_token_lookup_hash.sql`: adds `refresh_token_lookup_hash` to sessions (for accounts).
- `004_rate_limits_unique_constraint.sql`: unique constraint on `rate_limits(ip_address, endpoint)` for atomic upsert.
- `migrate.ts`: Migration runner with `schema_migrations` table tracking.
- `plantPersistence.ts`: Versioned binary serialization/deserialization of `Plant` node graphs (structure-of-arrays, typed arrays, no per-node DB rows). Quantized positions (1/64 unit), angles (16-bit). `PlantPersistence` class with save/load/delete/list methods. Envelope: magic `PLNT`, u16 version, u32 length, u32 CRC32. Growable buffer handles arbitrary node counts. `age` as float64. `event_log` persisted per save.

### Server integration (`apps/server/src/main.ts`)
- Database initialization runs migrations before listening.
- Loads all plants on startup via `PlantPersistence.loadAllPlants()`.
- Periodic save every 30s (time-sliced via unref'd interval) with **per-plant try/catch**.
- Save all plants on graceful shutdown (SIGINT/SIGTERM) with per-plant try/catch.
- Passes online plant IDs to `PlantWorld.step()` for tier management.

### Offline simulation tiers — Part 13.6 (`apps/server/src/ops/plantWorld.ts`)
- **Active** (online plants + anything touching them): full 20 Hz tick, full growth/damage/resources.
- **Near** (offline plants within interaction range of Active, or in weather/herbivore event): reduced 5 Hz tick, damage scaled by `offline_damage_multiplier`.
- **Dormant** (all other offline plants): coarse step at configurable interval (default 30s), catch-up integration computes elapsed upkeep/resource analytically instead of replaying ticks.
- Tier transitions driven by online status and proximity to Active plants (configurable interaction range).
- `GAME_EVENTS.PLANT_TIER_CHANGE` emitted on tier change.

### Interest management — Part 13.7 (`apps/server/src/ops/interestManager.ts`)
- Spatial grid cells (config `cell_size`, default 64×64 world units).
- Client subscribes to its cell + ring of neighbors (config `interest_ring_radius`, default 1).
- Per-client entity cap (config `per_client_entity_cap`, default 200).
- Distance bands → detail levels: L0 (≤50), L1 (≤150), L2 (≤500), L3 (minimap only).
- `InterestManager` tracks client subscriptions, entity positions, and provides `getEntitiesForClient()`.

### Event bus (`apps/server/src/ops/eventBus.ts`)
- In-process publish/subscribe with named events (`GAME_EVENTS`).
- Subscribers register at startup; handlers never block tick.
- Sync and async publish methods.
- Events: `PLANT_CREATED`, `PLANT_GROWTH`, `PLANT_DAMAGE`, `PLANT_DEATH`, `PLANT_TIER_CHANGE`, `PLAYER_JOINED`, `PLAYER_LEFT`, `RESOURCE_UPDATE`, `TICK_BUDGET_WARNING`.

### Tick-budget metrics — Part 13.6
- `PlantWorld.step()` returns per-tier timing (`activeMs`, `nearMs`, `dormantMs`, `totalMs`).
- `checkTickBudget()` warns via `TICK_BUDGET_WARNING` event when Active share exceeds `tick_budget_active_share` (default 0.7) or Active time exceeds `tick_budget_warn_threshold_ms` (default 40ms).
- World logs tier timing and tier stats every 100 ticks.

### Binary protocol — Part 13.8 (JSON transport, binary framing planned)
- `config/network.json`: `binary_protocol_enabled`, `position_quantization` (64), `angle_quantization_bits` (16), `rate_limit_per_type`.
- Wire format: `[version:u8][type:u8][payload]` with quantized integers for hot messages.
- Current transport: WebSocket + JSON at 20 Hz (see `docs/protocol.md` for full message types).

### Reconnect & Reclaim (2026-11-08/09)
- **Authenticated**: HELLO with `accessToken` → reclaim by `accountId`.
- **Anonymous**: HELLO with `plantId` → reclaim by `anon_<plantId>`.
- Reconnect window: 5 min (config `reconnect_window_min`). Plant not removed until window expires.
- `PLANT_REMOVED` only fires on window expiry or actual death.
- `ConnectionRegistry` manages socket lifecycle (one message handler, HELLO timeout, clean post-HELLO routing, old-socket transfer on reclaim).

### Config (`config/world.json`, `config/network.json`, `config/persistence.json`, `config/interest.json`)
- `world.json`: tick rates, tier config, cell size, interest radius, entity cap, snapshot interval, event log compaction, tick budget thresholds.
- `network.json`: protocol version, message size limits, world bounds, velocity validation, binary protocol flags, quantization, rate limits.
- `persistence.json`: `save_interval_ms` (30000), `event_log_max_entries` (1000).
- `interest.json`: `cell_size` (50), `max_entities_per_cell` (100), `subscribe_radius_cells` (2).

## Manual verification

- Start server with `DATABASE_URL` set → migrations run, plants load from DB.
- Connect two clients → both receive `WELCOME` with plant data (full node set).
- Grow plant on client A → server broadcasts `GROWTH_EVENT` to client B.
- Disconnect client → plant saved to DB, tier transitions to Dormant.
- Reconnect within window (5 min) → plant loads from DB, tier transitions to Active, `PLANT_SYNC` with full node set.
- Reconnect after window expires → new plant created, `PLANT_CREATED` broadcast.
- Observe tick budget logs every ~5s in server console.
- Verify `PLANT_TIER_CHANGE` events fire when players join/leave.
- Verify `WEATHER_UPDATE` broadcasts every tick.
- Verify `RESOURCE_QUERY` returns local tile with `tileX`/`tileZ`.

## Known limitations

- Binary protocol framing not yet implemented on wire (config only; current transport is JSON).
- Interest management not yet used to filter `STATE`/`KEYFRAME`/`GROWTH_EVENT` broadcasts (still broadcasts all plants to all clients).
- Dormant catch-up integration is simplified (no resource gain, only upkeep).
- Event log compaction not yet implemented as background job.
- `event_log` column in `world_plants` is written but not yet read back for replay.
