# T07 — Weather and Day/Night

**Status:** `[x]` Complete. Server-authoritative day/night cycle, clear/rain/thunderstorm state machine with 3-phase thunderstorm cycle (telegraph, active, aftermath), moisture soil deposition, weather-scaled daylight, and network broadcasts.
**Phase:** 1 — The Living Sprout. **Depends on:** T00A, T03.
**Config owners:** `config/weather.json`, `config/daynight.json` (both active).

## Scope delivered

### 1. Astronomical Day/Night Cycle (`config/daynight.json`)
- Continuous global `time_of_day` in range $[0.0, 1.0)$.
- Configurable cycle length (default 1800s / 30 minutes) and `day_fraction` (0.66).
- Condition mapping table for T13A booster integration:
  - `clear` $\to$ `sun`
  - `rain` $\to$ `rain`
  - `thunderstorm_telegraph` $\to$ `overcast`
  - `thunderstorm_active` $\to$ `storm`
  - `thunderstorm_aftermath` $\to$ `mist`

### 2. Weather State Machine (`config/weather.json`)
- Three canonical weather conditions:
  - **Clear**: Full daylight (`clear_light_multiplier = 1.0`), standard soil evaporation.
  - **Rain**: Soft cloud cover (`rain_light_multiplier = 0.7`), active moisture deposit to soil tiles (`2.0/s`).
  - **Thunderstorm**: 3 distinct sequential phases per DESIGN.md:
    1. **Telegraph (30s)**: Approaching darkness and overcast conditions.
    2. **Active (60s)**: Heavy precipitation (`5.0/s`), dim storm light (`0.3`), lightning frequency, and high wind force.
    3. **Aftermath (60s)**: Calming mist, lingering moisture.

### 3. ResourceWorld & Lighting Integration
- Server ticks advance both the astronomical orbit and weather state machine.
- Rain and active storm precipitation directly saturate the ground soil matrix.
- Weather light multiplier dims ambient and sun light on tiles and plants.
- Broadcasts `WEATHER_UPDATE` (message type 21) containing `timeOfDay`, `isDay`, `sunIntensity`, `weatherState`, `conditionToken`, and advance `forecast`.
- Three.js scene dynamically orbits sun light and scales illumination based on server broadcast.

### 4. Fixes (2026-11-08/09)
- Clear/rain durations no longer shadowed by zero defaults; all durations read from `WeatherConfig`.
- Next state is **preselected at state entry** (`machine.nextState`) so forecast equals the transition actually taken.
- Light multipliers and moisture rates come from config; no hardcoded defaults.
