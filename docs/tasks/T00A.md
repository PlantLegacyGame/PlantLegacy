# T00A — Resource model + onboarding

**Status:** `[ ]` onboarding slice only. The three-line hint card, resource
readout and tooltips exist; the tile grid, resource simulation, photosynthesis,
absorption, deposits and consumption triggers required by DESIGN.md are not
built.
**Phase:** 1 — The Living Sprout. **Depends on:** T00.
**Config owner:** `config/onboarding.json` (draft). The DESIGN.md owners
`config/resources.json` and `config/daynight.json` are still stubs.
**Commits:** `d98adaf` (onboarding config, route, overlays), `14ac7da`
(staging deploy of the T00A client).

## Scope delivered

- `config/onboarding.json` with 3 values: `hint_card_lines`,
  `show_hint_card_duration_ms`, `resource_tooltips`.
- `GET /config/onboarding` reads the file and falls back to built-in defaults.
- Three-line first-spawn hint card (RULE_13), shown after `WELCOME` and faded
  out after the configured duration.
- Light / water / minerals readout with hover tooltips loaded from config.
- No client-side resource writes.

## Manual verification

- `pnpm dev`, open `http://localhost:4173`.
- After `WELCOME`, the three-line card appears and fades.
- Hovering each ⓘ shows the configured tooltip.
- The readout is present but stays at `0.00`.

## Known limitations

- The full T00A resource model is not implemented: no tile grid, no simulation,
  no server broadcast, no photosynthesis, no absorption or deposits, no
  consumption triggers.
- The readout values are placeholders.
- The hint card is not manually dismissible (DESIGN.md asks for dismissible).
- Default onboarding text is duplicated in `apps/server/src/main.ts` and
  `apps/client/src/main.ts`; both should fail or read config instead of
  embedding values (RULE_3).
