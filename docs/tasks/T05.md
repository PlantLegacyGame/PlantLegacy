## 1. What shipped

### Chat (T05 core)
- Chat panel bound to **`T`**, with **proximity** and **world** tabs.
- Send/broadcast flow end-to-end: client `CHAT_MESSAGE` (type 9), server
  validation and rate limiting, broadcast `CHAT_BROADCAST` (type 23).
- Proximity chat is range-limited by `chat.proximity_range_px`; world chat is
  global and rate-limited by `chat.world_rate_msg_per_min`.
- Per-session chat log capped by `chat.log_size`; message length capped by
  `chat.message_max_chars`.
- World chat sits behind the per-connection message budget
  (`net_proto.max_messages_per_second`, `message_burst`).

### Emotes
- Emote wheel bound to **`E`**, driven by `emotes.emote_definitions` (data, not
  code). Selecting an emote sends `/emote <id>` through the chat path.
- An emote rides the chat message it was typed with; nothing limits it by distance.
- `G` is free for the emote wheel because ADR-018 removed quick-grow.

### Block and report
- Block and report controls appear on **every chat message**.
- `BLOCK` (type 30) mutes/unmutes a player's chat; it does not touch world
  simulation.
- `REPORT` (type 29) stores reporter, target, surface, reason, free text and a
  context snapshot: the last `reports.context_line_count` lines of the channel.
  Free text is capped by `reports.report_free_text_max`; submissions are limited
  by `reports.report_rate_limit_per_min`; the in-memory queue is bounded by
  `reports.reports_in_memory_max`.
- Report reasons are config data (`reports.report_reasons`), restricted to the
  RULE_6 illegal-content categories. There is no general moderation queue
  (RULE_6, RULE_12) — admin triage is T40.

## 2. Protocol

| Type | Name | Direction | Notes |
|---|---|---|---|
| 9 | `CHAT_MESSAGE` | client → server | chat line or `/emote <id>` |
| 23 | `CHAT_BROADCAST` | server → client | chat or emote from another player |
| 29 | `REPORT` | client → server | report with context snapshot |
| 30 | `BLOCK` | client → server | mute/unmute a player's chat |

Type `10` is `WELCOME`; `REPORT` originally collided with it and every report was
silently dropped. That history is recorded in `docs/protocol.md`.

## 3. Acceptance (DESIGN T05), against what exists

| Criterion | State | Evidence |
|---|---|---|
| Proximity chat range-limited | Met | `chat.proximity_range_px` |
| World chat global and rate-limited | Met | `chat.world_rate_msg_per_min` |
| Emotes data-driven | Met | `emotes.emote_definitions` |
| Chat log persists per session | Met | `chat.log_size` |

## 5. Tests

No dedicated unit tests exist for chat, block or report: those paths were verified
by hand (two tabs, world and proximity channels, emote wheel, block, report) and
by the server-side schema validation and rate limits. That is an honest gap, not
a pass — the report context snapshot and the block filter are the two paths
worth a regression test when T40 adds triage.

## 6. Not built

- Report entry points on surfaces that do not exist yet (see §3).
- Admin triage UI, age gate, legal pages — all **T40**.
- Persistence of reports beyond the bounded in-memory store; the `reports` table
  arrives with T40.
